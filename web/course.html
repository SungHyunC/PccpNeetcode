    0 이 페이지를 연 뒤로, 파이썬이 할 수 있었던 단순 연산의 수 (초당 약 1,000만 번)

    N이 모든 것을
    정한다

    문제를 읽기 전에 제한사항부터 보세요. 입력 크기 N 하나가 쓸 수 있는 알고리즘을 거의 다 골라 줍니다.

    모든 문제의 첫 단계복잡도docs/01-complexity.md

    채점 서버는 친절하지 않습니다. 정답을 내더라도 제한 시간을 넘기면 0점입니다. 그래서 고수들은 코드를 쓰기 전에 계산부터 합니다. "이 방법이면 연산을 몇 번 하지?"

    기준은 단순합니다. 파이썬은 1초에 대략 1,000만(10⁷) 번의 단순 연산을 합니다. 연산 횟수가 이 선을 넘으면 위험하고, 100배 넘으면 확실히 시간 초과입니다. 오른쪽 그림을 보며 스크롤해 보세요.

    N = 8

    작은 N 에서는 무엇이든 통과합니다. 모든 순서를 다 해 보는 O(N!) 도 4만 번이면 끝납니다. N ≤ 10 이면 완전탐색을 의심하세요.

    N = 20

    N! 은 이미 10¹⁸ 을 넘었습니다. 하지만 2ᴺ 은 약 100만. 각 원소를 넣을지 말지 정하는 부분집합·백트래킹은 아직 됩니다.

    N = 3,000

    2ᴺ 은 우주의 나이를 넘었습니다. 이제 O(N²) 이 900만 번으로 선에 걸칩니다. 2중 반복문, 2차원 DP의 영역입니다.

    N = 100,000

    코딩 테스트에서 가장 흔한 크기입니다. O(N²) 은 100억 번, 약 17분. 여기서 필요한 것은 O(N log N) 이하: 정렬, 힙, 이분 탐색, 해시, 투 포인터.

    N = 1,000,000,000

    배열을 한 번 훑는 것조차 100초. 남은 건 O(log N) 뿐입니다. 답의 범위를 반씩 줄이는 이분 탐색, 혹은 수학 공식.

    이 표를 외우면 문제를 읽는 순서가 바뀝니다. 지문보다 먼저 제한사항에서 N 을 찾고, 목표 복잡도를 정하고, 그 복잡도로 가능한 도구만 머릿속에 남깁니다.

    N ≤ 10⁵ 이면 이중 for 문은 쓰기도 전에 지운다.
    01

    기억하는 데
    드는 비용

    "이미 본 적 있나?" 를 O(1) 에 답할 수 있다면, 안쪽 반복문 하나가 통째로 사라집니다.

    PCCP 단골인터뷰 1순위해시 · set · dictdocs/02-arrays-hashing.md

    배열에서 더해서 target 이 되는 두 수를 찾는다고 합시다. 가장 먼저 떠오르는 방법은 모든 쌍을 확인하는 것입니다. N 개면 쌍은 N(N-1)/2 개. N 이 10만이면 50억 번입니다.

    그런데 지금 보고 있는 수가 x 라면, 필요한 짝은 정해져 있습니다. target − x. 그 값을 "전에 본 적이 있는지"만 알면 됩니다. 해시맵(dict)은 이 질문에 평균 O(1) 로 답합니다. 메모리를 조금 써서 시간을 사는 거래입니다.

    
        
    순서가 중요합니다. 자기 자신을 먼저 기록하면 target 이 6 이고 x 가 3 일 때 자기 자신과 짝을 지어 버립니다. 확인 먼저, 기록은 나중.
    
        
    같은 거래, 다른 얼굴들
    
        
    "몇 번 나왔나" 는 Counter, "같은 그룹인가" 는 정규화한 키(정렬한 문자열)로 묶는 defaultdict(list), "합이 k 인 구간이 몇 개인가" 는 누적합을 dict 에 세는 방식. 모두 같은 아이디어입니다. 기억해 두면 다시 찾지 않아도 된다.
    
        
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    02
    
          
    두 손가락으로
    훑기
    
          
    왼쪽 끝과 오른쪽 끝이 각각 한 방향으로만 움직이면, 반복문이 겹쳐 보여도 전체는 O(N) 입니다.
    
          
    인터뷰 단골투 포인터 · 슬라이딩 윈도우docs/03 · docs/04
    
        
    
        
    "조건을 만족하는 가장 긴 연속 구간" 을 찾는 문제는 모든 시작점과 끝점을 다 보면 O(N²) 입니다. 하지만 구간을 창문이라고 생각하면 다르게 볼 수 있습니다.
    
        
    오른쪽 끝 r 을 한 칸씩 늘립니다. 창문 안이 조건을 어기면 왼쪽 끝 l 을 조건이 다시 맞을 때까지 당깁니다. l 과 r 은 절대 뒤로 가지 않습니다. 그래서 두 손가락이 움직이는 총 횟수는 많아야 2N 번입니다.
    
      
    
      
      
    
        
    for 안에 while 이 있다고 O(N²) 이 아니다. 각 원소가 몇 번 들어오고 나가는지를 세라.
    
        
    이런 계산법을 상각 분석(amortized analysis) 이라고 부릅니다. 면접에서 "while 문이 안에 있는데 왜 O(N) 인가요?" 라는 질문이 나오면 이렇게 답하세요. "Each index enters and leaves the window at most once."
    
        
    단, 슬라이딩 윈도우에는 전제가 있습니다. 창을 넓힐수록 조건이 한쪽으로만 변해야 합니다. 음수가 섞인 배열에서 "합이 k" 를 찾을 때는 창을 넓혀도 합이 줄 수 있으므로, 1장의 누적합 + 해시로 돌아가야 합니다.
    
        
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    03
    
          
    아직 답을 못 찾은
    것들의 줄
    
          
    "다음으로 더 큰 값은 언제 나오나?" 를 묻는 문제에서, 스택은 기다리는 원소들의 대기실입니다.
    
          
    PCCP 단골스택 · 단조 스택docs/05-stack.md
    
        
    
        
    매일의 기온이 주어지고, 각 날에 대해 "며칠을 기다려야 더 따뜻해지는가" 를 구한다고 합시다. 각 날마다 앞으로 쭉 훑으면 O(N²) 입니다.
    
        
    거꾸로 생각해 봅시다. 오늘 기온이 25도라면, 아직 더 따뜻한 날을 만나지 못한 과거의 날들 중 25도보다 추웠던 날은 오늘이 바로 그 답입니다. 그 날들을 줄에서 빼면서 답을 적습니다. 줄에 남는 날들은 자연스럽게 기온이 내려가는 순서가 됩니다. 이것이 단조 스택(monotonic stack) 입니다.
    
      
    
      
      
    
        
    
        
    각 날은 스택에 한 번 들어가고 한 번 나옵니다. 그러니 이것도 O(N). 괄호 짝 맞추기, 히스토그램에서 가장 큰 직사각형, 주식 가격이 떨어지지 않은 기간도 모두 같은 "대기실" 패턴입니다.
    
        
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    04
    
          
    절반씩
    버리기
    
          
    답을 직접 찾기 어렵다면, 답을 하나 찍고 "이 정도면 되나?" 만 물어보세요. 예/아니오가 한 번만 바뀐다면 이분 탐색이 됩니다.
    
          
    PCCP 고난도 단골이분 탐색 · 파라메트릭 서치docs/06-binary-search.md
    
        
    
        
    1부터 1,000 사이의 숫자 하나를 맞히는 게임을 해 봅시다. 틀릴 때마다 "더 크다/작다" 만 알려 줍니다. 아래 게임에서 직접 해 보고, 이분 탐색에게도 맡겨 보세요.
    
      
    
      
      
    
        
    매번 남은 범위의 가운데를 고르면 범위가 절반이 됩니다. 1,000 → 500 → 250 → … → 1. 2¹⁰ = 1,024 이므로 10번이면 무조건 맞힙니다. 범위가 10¹⁸ 이어도 60번이면 됩니다.
    
        
    파라메트릭 서치: 답을 찍고 물어보기
    
        
    PCCP 의 단골 '입국심사' 유형을 봅시다. 심사관마다 한 명을 처리하는 시간이 다르고 (예: 7분, 10분), n 명을 모두 심사하는 최소 시간을 구합니다. 시간을 직접 계산하기는 어렵습니다. 하지만 "T 분이 주어지면 몇 명을 처리할 수 있나?" 는 쉽습니다. sum(T // t for t in times).
    
        
    그리고 T 가 커질수록 처리 인원은 줄지 않습니다. 즉 "n 명 처리 가능?" 의 답은 아니오, 아니오, …, 예, 예, 예 처럼 딱 한 번 바뀝니다. 그 경계를 이분 탐색으로 찾으면 됩니다.
    
      
    
      
      
    
        
    
        
    "최소 시간", "최대 거리" + 입력이 10⁹ 이상 → 파라메트릭 서치 의심.
    
        
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    05
    
          
    아이들에게 묻고
    위로 올리기
    
          
    트리 문제의 대부분은 같은 질문입니다. "왼쪽과 오른쪽 서브트리가 답을 알려 준다면, 나는 무엇을 계산하면 되나?"
    
          
    인터뷰 최다 출제트리 · 재귀 · DFS/BFSdocs/08-trees.md
    
        
    
        
    트리를 방문하는 순서는 네 가지입니다. 노드 자신을 언제 처리하느냐의 차이입니다. 내려가기 전(전위), 왼쪽을 다녀온 뒤(중위), 양쪽을 다 다녀온 뒤(후위), 그리고 층별로(레벨 순서, BFS).
    
      
    
      
      
    
        
    이진 탐색 트리(BST)를 중위 순회하면 값이 정렬된 순서로 나옵니다. "BST 에서 k 번째로 작은 값" 같은 문제가 바로 풀리는 이유입니다.
    
        
    그리고 가장 강력한 것은 후위 순회 모양의 재귀입니다. 아이들에게 먼저 물어보고, 그 답으로 내 답을 만들어 위로 올립니다. 높이, 지름, 균형 여부, 경로의 최대 합이 모두 이 틀에 들어갑니다.
    
        
    
        
    재귀를 믿어라. 아이들의 답이 맞다고 가정하고 내 한 줄만 쓴다.
    
        
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    06
    
          
    가장 작은 것만
    꺼내 주는 상자
    
          
    전체를 정렬할 필요가 없을 때가 있습니다. 매번 가장 작은(또는 큰) 하나만 필요하다면 힙이 O(log N) 에 꺼내 줍니다.
    
          
    PCCP 단골힙 · 우선순위 큐 · heapqdocs/10-heap.md
    
        
    
        
    힙은 배열 하나로 만든 완전 이진 트리입니다. 인덱스 i 의 아이는 2i+1 과 2i+2, 부모는 (i−1)//2. 규칙은 하나뿐입니다. 부모는 아이보다 작거나 같다. 그래서 맨 위(인덱스 0)가 항상 최솟값입니다.
    
        
    값을 넣으면 맨 끝에 붙인 뒤 부모보다 작은 동안 위로 올라갑니다. 꺼낼 때는 맨 끝 값을 맨 위로 옮긴 뒤 아이보다 큰 동안 아래로 내려갑니다. 둘 다 트리의 높이, 즉 log N 번이면 끝납니다.
    
      
    
      
      
    
        
    
        
    "k 번째로 큰 값" 은 크기 k 짜리 최소 힙을 유지하면 됩니다. 힙이 k 개를 넘으면 가장 작은 것을 버립니다. 마지막에 맨 위에 남은 값이 답입니다. O(N log k).
    
        
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    07
    
          
    물결처럼
    퍼지는 탐색
    
          
    BFS 는 가까운 곳부터 차례로 퍼집니다. 그래서 가중치 없는 그래프에서 처음 도착한 순간이 곧 최단 거리입니다.
    
          
    PCCP 최다 출제BFS · DFS · 격자docs/12-graphs.md
    
        
    
        
    미로의 왼쪽 위에서 오른쪽 아래까지 가장 빨리 가는 길. PCCP 에서 가장 자주 보는 모양입니다. 큐(deque)를 쓰면 BFS, 스택을 쓰면 DFS 가 됩니다. 아래 미로에서 두 방법을 번갈아 실행해 보세요. 칸을 눌러 벽을 바꿀 수 있습니다.
    
      
    
      
      
    
        
    BFS 는 거리 1 인 칸을 모두 본 뒤에야 거리 2 인 칸으로 갑니다. 물에 돌을 던졌을 때 퍼지는 물결과 같습니다. DFS 는 한 방향으로 끝까지 파고들기 때문에 도착은 하지만 최단 경로라는 보장이 없습니다.
    
        
    
        
    방문 표시는 꺼낼 때가 아니라 넣을 때. 안 그러면 같은 칸이 큐에 여러 번 들어간다.
    
        
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    08
    
          
    확정된 거리부터
    넓혀 가기
    
          
    간선마다 비용이 다르면 BFS 의 물결은 깨집니다. 다익스트라는 "지금 가장 가까운 곳" 을 힙에서 꺼내며 물결을 다시 만듭니다.
    
          
    PCCP 4번 문제급다익스트라 · 힙docs/13-advanced-graphs.md
    
        
    
        
    규칙은 하나입니다. 아직 확정되지 않은 노드 중에서 출발점과 가장 가까운 것을 꺼내면, 그 거리는 확정입니다. 음수 간선이 없다면 다른 길로 돌아와서 더 짧아질 수 없기 때문입니다. 꺼낸 노드에서 이웃으로 가는 거리를 갱신(relax)하고, 갱신된 것은 힙에 넣습니다.
    
      
    
      
      
    
        
    
        
    if d > dist[u]: continue 한 줄이 중요합니다. 같은 노드가 힙에 여러 번 들어갈 수 있는데, 낡은 항목을 버리는 줄입니다. 이 줄이 없으면 정답은 나와도 시간 초과가 날 수 있습니다. 전체 복잡도는 O(E log V).
    
        
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    09
    
          
    같은 질문에
    두 번 답하지 않기
    
          
    DP 는 마법이 아닙니다. 작은 문제의 답을 적어 두고 다시 쓰는 것뿐입니다. 어려운 건 "작은 문제" 를 정의하는 일입니다.
    
          
    PCCP · 인터뷰 공통 난관DP · 메모이제이션docs/14 · docs/15
    
        
    
        
    피보나치 수 f(n) = f(n−1) + f(n−2) 를 그대로 재귀로 짜면 같은 계산을 셀 수 없이 반복합니다. 아래 그림에서 n 을 키워 보세요. 그리고 메모를 켜 보세요.
    
      
    
      
      
    
        
    메모가 없으면 호출 수는 약 1.6ⁿ 로 늘어납니다. 메모가 있으면 각 n 을 한 번씩만 계산하므로 약 2n 번입니다. DP 의 시간 = 상태의 개수 × 상태 하나를 계산하는 비용. 이 공식 하나로 모든 DP 의 복잡도를 셀 수 있습니다.
    
        
    상태를 정하는 연습: 동전 거스름돈
    
        
    동전 [1, 2, 5] 로 11원을 만드는 최소 개수. 상태는 "x 원을 만드는 최소 동전 수" = dp[x]. 마지막에 쓴 동전이 c 라면 나머지는 dp[x − c] 입니다. 그래서 dp[x] = min(dp[x − c] + 1). 작은 금액부터 채워 나가면 됩니다.
    
      
    
      
      
    
        
    DP 5단계: 상태 정의 → 점화식 → 초기값 → 계산 순서 → 답의 위치.
